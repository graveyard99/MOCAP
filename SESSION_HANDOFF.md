## Owner's intended outcome

The owner asked for an actual built system, not architecture/pseudocode/research alone: an open-source, production-oriented RGB multi-camera markerless VFX tool producing metric trajectory, persistent actor proportions, skeletal pose/orientation, contacts and a SMPL-family character. The principal deliverable is a conventional rigged, skinned, animated FBX, not a mesh sequence. Arbitrary camera counts, moving cameras, affine asynchronous timing, native timestamps, continuous motion and explicit metric calibration are fundamental requirements.

The principal doctrine is: measure what can be measured, infer only unobserved quantities, preserve uncertainty, and prevent weaker evidence from overwriting stronger evidence. Trust order is surveyed/calibrated geometry → robust multiview geometry → temporal observations → body constraints → biomechanics → learned motion priors → monocular estimates. Manual/authoritative camera and synchronization locks must survive every subsequent solve. Shape is persistent across frames. Physics is optional, downstream and confidence-bounded.

All project-managed dependencies, environments, tools where portable, model checkpoints, caches, temporary files and working projects must remain below the selected installation root. No global pip or home-cache pollution; GPU/OS drivers remain separately detected system prerequisites. The owner requested deterministic locking, real tests/demos, Git organization, truthful status and external-asset documentation.

The owner appended a **hard desktop GUI requirement**, with a shared service/API under GUI and CLI, asynchronous jobs, project manager/wizard, viewers, camera/synchronization/actor/QC/export workspaces, non-destructive corrections, stale results, undo/preferences and usable launchers. Ordinary artist operation must eventually avoid configuration editing or remembering CLI commands. A full operator manual and reproducible beginner tutorial are required. The current GUI is a tested coherent preview, with important advanced workflows still incomplete; do not reduce that original acceptance bar to “has a GUI.”

## Useful development context that source alone may not explain

1. **Why the example is a mannequin:** real SMPL-family numerical assets were unavailable. A deterministic original humanoid/LBS fixture allowed the actual geometry→persistent shape→local rotations→weighted animated FBX pipeline to be built and independently re-imported. It is deliberately labeled synthetic and never substituted when a requested SMPL family is missing.
2. **No weights have been acquired:** the current RTMW/YOLOX/PPHumanSeg presets, downloader and verification tool are preparation/integration work. Generated ONNX fixtures test actual ONNX Runtime contracts, but are not those pretrained models. A segmentation request manifest explicitly records no successful acquisition/inference. Empty model directories are expected at transfer.
3. **Cloud network stalls were outside the download process:** default sandbox access could not connect to the session proxy. Additional-permission commands waited before execution and were aborted, sometimes far beyond curl's own timeout. Do not infer publisher downtime, invalid model licenses or unavailable desktop networking from those attempts. Do not repeat long permission waits merely to re-prove the cloud limitation.
4. **Numerical threading mattered:** the initial Qt/full-solve validation encountered heavy numerical thread oversubscription. Profiling led to a project-local default of one BLAS/OpenMP/MKL thread; a solve reduced from roughly 40 s to roughly 4.3 s. This was a measured correction, not a blanket prohibition on future parallelism.
5. **Real export was prioritized:** Blender creates a persistent weighted mesh and conventional skeleton, rotation/root animation and optional pose correctives, then validates first/last deformed samples in a clean re-import scene. An actual USD attempt failed because the system Blender lacked its operator; it was not relabeled successful. Other DCCs have not been tested.
6. **Several governance repairs are already done:** raw observation overrides preserve source indexing and hash binding; trusted calibration overrides survive import; inference edits invalidate early stages; final contact-refined animation is separated from the body checkpoint; contact QC measures the fitted rig. Do not resurrect these abandoned incorrect approaches.
7. **Current audit exposed additional bugs:** the 147 passing tests do not cover singular covariance, sparse shape evidence, some downstream camera-confidence weights, GUI native-PTS display, whole-body edges, full-range reset or out-of-band stale export. These source-backed defects are enumerated in PROJECT_STATE and remain unfixed intentionally for this documentation-only task.
8. **No general GPU installer exists:** bootstrap creates the isolated CPU Linux environment and launchers. It does not obtain SMPL, install drivers, set up a validated CUDA stack, or prove checkpoint inference. CUDA fallback is rejected by the inference adapter, but that contract was tested with fixtures/mocks rather than actual GPU hardware.
9. **Source archive versus Git history:** the cloud source ZIP was made with `git archive` and has no `.git`. A local clone or transfer bundle is necessary to retain commit history. Installed env/cache/generated demo/OS binaries are separate from tracked source and must be recreated or explicitly transferred when appropriate.

These are engineering decisions/discoveries, not additional owner instructions. No other specific user correction to an algorithm is established in the visible conversation.
